# Review 指南

改编自 AWZ Workflow `workflows/review-and-fix.md`。一次性只读 review 直接报告发现；跨多轮、包含修复或需要持续追踪时，复制 `../templates/review-checklist.md` 到 `../plans/` 维护。

## 优先级

- `P0`：数据丢失、严重安全/隐私风险、主流程不可用、构建/启动完全失败。
- `P1`：明确 bug、重要 regression、用户可见错误、关键测试缺失。
- `P2`：维护性风险、边界处理不足、性能隐患、体验明显不顺。
- `P3`：轻量清理、命名、注释、低风险 polish。

## Checklist item

```text
- [ ] [P1] 文件或模块：问题描述
  - 修复计划：
  - 验证方式：
  - 当前状态：
```

修复完成后把 `[ ]` 改成 `[x]`，并补一句验证结果。过程文档要与最终说明对齐，不能只在回复里说完成。

## 自我 review

单一维护者没有第二双眼睛，提交前对自己的 diff 做一次对抗式阅读：

1. 这个改动在什么输入下会出错？
2. 有没有顺手改了任务之外的东西？
3. 文档、命令和真实实现是否一致？
4. 验证覆盖了改动的主要风险吗？
