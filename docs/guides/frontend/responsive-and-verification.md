# 响应式与验证

## 读取条件

用于多端适配、布局重排、交付前验收，以及涉及滚动、overlay、复杂状态或可访问性的界面。

## 响应式不是缩放

在布局关系开始失效的位置设置断点，并重新判断：

- 小屏的第一优先级是什么，信息顺序是否需要改变；
- 桌面横向关系应改为纵向、折叠、分步还是独立页面；
- hover、scroll、右键和快捷键是否需要触摸或可见控件替代；
- 固定导航、sticky 区域、侧栏和内部滚动在小屏是否仍合理；
- 标题换行、正文行宽、表格、图表和图片裁切是否重新设计；
- loading、empty、error 和长内容是否仍占用稳定空间。

不要只验证几个固定设备宽度；边界内容、长文本、缩放和中间宽度更容易暴露问题。

## 真实浏览器验收

按风险选择必要组合，不机械跑满矩阵：

- 首次加载、刷新和路由返回；
- 常见桌面、窄桌面与移动宽度；
- loading、empty、error、success、disabled 和超长内容；
- modal、toast、popover、菜单、表单校验和 destructive confirmation；
- 鼠标、键盘、触摸替代路径、focus 顺序和滚动行为；
- 明暗主题、缩放、对比度与 `prefers-reduced-motion`；
- 控制台 warning/error、布局偏移、动画卡顿与资源加载失败。

先观察实际页面，再改代码；交互后检查最终状态，不只看进入动画的截图。

## 完成标准

- 没有 overlap、clipping、意外内部滚动或不可达控件。
- 主要任务在不同宽度下仍清楚，视觉焦点没有失序。
- 关键控件状态稳定，文本和数据变化不会造成无意义跳动。
- 可访问路径和低动效路径不丢信息、不丢操作。
- 最终说明列出实际验证的 viewport、状态和未覆盖风险。
