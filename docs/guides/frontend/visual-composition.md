# 视觉构图

## 读取条件

用于新页面、较大改版、品牌表达、排版重构或视觉层级不清。普通组件修复不读。

## 决策顺序

1. 明确产品类型、首要任务与第一视觉焦点。
2. 先画稳定空间骨架：导航、工作区、上下文、主操作分别在哪里。
3. 再用字体、尺度、留白、明度和媒体建立层级。
4. 最后才添加边框、圆角、阴影、渐变和装饰图形。

## 构图规则

- 每个页面或 section 只承担一个主要任务，不让标题、CTA、图表和装饰同时抢最高层级。
- 内容或状态变化时尽量保留对齐线和共享结构，避免整个页面重新排队。
- card 不是默认分组方式；优先使用空间、列、分隔线、列表和背景层级。
- 排版必须形成角色差异：标题建立焦点，正文承担理解，label 和 metadata 负责定位。
- 小字号只给真正次要的信息；中文、英文和混排分别验证行高、换行与密度。
- 留白用于分组、节奏和聚焦，高密度界面也要保留局部呼吸，不平均塞满。
- 图像、插图、图表或背景图形必须承担证明、解释、导航或氛围职责；纯装饰应能被删除。
- 首页、列表、详情、设置和异常状态应共享同一视觉语言，而不是只有首屏精致。

## 强度边界

- 效率型界面减少氛围装饰，把强调留给操作、状态和异常。
- 内容型界面优先阅读宽度、章节节奏和定位能力。
- 品牌型界面可以让首屏成为视觉主场，但 CTA 和内容路径必须清楚。
- 叙事型界面可以使用非常规构图，但需要可发现的导航与常规交互替代路径。

## 交付自检

- 隐去边框、阴影和装饰后，层级是否仍然成立？
- 扫一遍标题、label 和关键数字，能否理解页面？
- 是否只有一到两个真正主角？
- 每个 card 是否确实代表独立对象或交互边界？
- 媒体去掉后损失的是信息，还是只有“炫”的感觉？
