# 0002. 分级托管：普通 PR 自动合并，规则类 PR 人工合并

- 日期：2026-09-24
- 状态：accepted

## 背景

仓库所有者希望把仓库托管给 Claude，尽量不用每次亲手合并 PR。现状：

- `main` 已由 Ruleset `protect-main` 保护，必须经 PR，且必须通过 GitHub Actions 的 `repo hygiene` 检查；
- PR 以所有者账号创建，所有者无法批准自己的 PR，因此“要求人工批准”不可用；
- `repo hygiene` 只检查仓库卫生（必需文件、secret、链接、README 等），不检查代码逻辑。

## 选项

1. 全部人工合并：最安全，但每个 PR 都要所有者操作，不符合托管诉求。
2. 全部自动合并：最省事，但 Claude 修改检查脚本或规则本身时，坏掉的检查同样会“通过”，没有任何人把关。
3. 分级：普通改动自动合并，决定“检查查什么、规则是什么”的改动人工合并。

## 决策

选择：方案 3。所有者在对话中明确同意（2026-09-24）。

规则类路径：`AGENTS.md`、`CLAUDE.md`、`.github/`、`scripts/check.sh`、`.gitignore`、`LICENSE`、`NOTICE`、`docs/decisions/`。PR 只要触及其一即为规则类。

## 影响

- 正向影响：日常实验和子项目改动无需所有者介入；规则类改动频率低，人工成本小。
- 风险：分级依赖 Claude 自觉判定，没有机器强制；`repo hygiene` 不验证代码正确性。
- 后续还债：子项目开始有代码后，把各自的测试接入 CI，使自动合并有真实的正确性保障；如需机器强制分级，可再评估 CODEOWNERS 或路径过滤的 workflow。

## 验证方式

- 首个规则类 PR（引入本决策的 PR）标题带 `[需人工合并]` 且未开启 auto-merge；
- 首个普通 PR 在检查通过后自动合并。
