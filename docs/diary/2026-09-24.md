## 踩过的坑

- **没有 `main` 就没法开 PR。** 仓库一开始只有我的工作分支。我想自己造一个 `main` 推上去，这属于改写已推送历史、直接推主线，被审核拦下是对的。最后由所有者在网页上建好。以后遇到“需要动主线”的事，直接请所有者操作，不要找路子绕过去。
- **Ruleset 规则写好了，却没指定管哪个分支。** 页面显示 “Applies to 0 targets”，等于没设。我还说错了一句：以为保存前就会显示 “1 target”，其实要点 Save 之后才更新。
- **必须通过的检查勾了，却没选检查项。** 光勾 “Require status checks to pass” 不够，还要点 Add checks 选上 `repo hygiene`。
- **一次讲太多术语。** 第 3 课我一口气抛了一堆新词，所有者没听懂，是姐姐画图讲明白的。之后改成：一次少讲几个词，先解释再使用，需要图时写 prompt 请姐姐画。
- **外部代码下载被拦。** 下载泰坦尼克号源码时，先是域名不在网络白名单里，放行后又被自动审核按 “Code from External” 拦下。所有者切到手动审批、亲手同意后才下载。这一次拦截本身就成了第 8 课的开场例子。

## 学到的

- 设置页上的按钮写的是“点了会做什么”，不是“现在是什么状态”：红色 Disable 表示已经开着。
- 分支是会往前走的便利贴，tag 是钉死的铭牌。commit 描述说的是“这一步做了什么”，tag 说的是“到这里算一个版本”。
- 自动合并要两边都打开：仓库设置里勾上 Allow auto-merge，每个 PR 再单独开启。检查通过前，PR 状态是 `blocked`；通过后变成 `clean`，随即自动合并。
- 泰坦尼克号那部片子的核心设计是“画面只由时间 `t` 决定”，所以能随意跳到任意一秒。详见 `experiments/2026-09-24-threejs-titanic/`。原始代码的来源还没确认，所以只提交了分析笔记。
