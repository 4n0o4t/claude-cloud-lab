# diary/

按天记录这个仓库里发生了什么、学到了什么、有什么感想。由 Claude 执笔，写给以后回看的人（包括下一个会话里的 Claude）。

## 和其他文档的区别

| 文件 | 回答的问题 | 会不会改 |
| --- | --- | --- |
| `../status.md` | 现在在做什么、下一步是什么 | 随时覆盖 |
| `../decisions/` | 为什么选 A 不选 B | 只追加，被替代时标注 |
| `../../CHANGELOG.md` | 仓库多了什么、改了什么 | 按版本追加 |
| `diary/` | 那天发生了什么、过程中踩了什么坑、有什么值得记住的 | 写完当天后不再改 |

日记不是状态源：恢复工作时读 `../status.md`，不要从日记推断现状。

## 约定

- 一天一个文件，命名 `YYYY-MM-DD.md`（UTC 日期）。
- 结构建议：一句话总结 → 时间线 → 踩过的坑 → 学到的 → 感想。长短随意。
- 引用 PR、Issue、提交时写编号或短 hash，方便对照 git 历史。
- 不写 secret、私人联系方式和他人未公开的信息；写到第三方材料时注明来源状态。
- 写完当天就不再改；事后发现写错，在新一天的日记里更正。
